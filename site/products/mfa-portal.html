MFA Portal · For RSA Authentication Manager

Coming soon

A self-service front door for RSA SecurID.

MFA Portal puts a user-facing web portal in front of RSA Authentication Manager. Token holders can find the Trusted Agent who supports them and set or update their own SecurID PIN, and program staff can manage token shipments across multiple sites — without routing every one of those requests through the help desk or the Authentication Manager console.

What it does

Trusted Agents

Find the right Trusted Agent

Token holders look up the Trusted Agent who can help them, instead of asking around or working from an out-of-date contact list when they need a token issued, replaced or verified.

SecurID PINs

Set or update a token PIN

Users set the PIN on a newly issued SecurID token, or change an existing one, from the portal. Authentication Manager still applies the PIN; the portal gives users a straightforward place to do it.

Token logistics

Ship tokens to multiple sites

Programs that support more than one location manage where tokens are being shipped and which site each shipment is for, in one place rather than across spreadsheets and email threads.

How it fits

  1. RSA Authentication Manager stays in charge. Tokens, PINs and authentication policy remain in the Authentication Manager deployment you already run. MFA Portal is a front end to it, not a replacement.
  2. Users get a portal, not a console. The everyday tasks token holders need — finding their Trusted Agent and managing their PIN — are available without access to administrative tooling.
  3. Program staff see every site. Token shipments for multiple locations are managed side by side, so distribution to a new or remote site is not a separate manual process.

Why it helps

Fewer PIN tickets

Routine PIN setup and changes are handled by the token holder, leaving the help desk free for the problems that need a person.

Less time lost finding help

A user who needs a Trusted Agent can find one directly, which matters most for new arrivals and people at smaller sites.

Distribution you can follow

Multi-site token shipping is managed in one place, so it is clear what is going where.
